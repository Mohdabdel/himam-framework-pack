## 1) تفسير موثق لاختلاف بيانات المعاينة

### السؤال

لماذا أظهر الفحص 4 حالات فقط، بينما ظهرت سابقًا `RC-2026-0001` … `RC-2026-0004` والحالة المسماة «ع»؟

### الحقائق المثبتة من الكود

- لا يوجد أي مخزن خادمي أو قاعدة بيانات في المشروع. تم التحقق: لا يوجد `src/integrations/supabase`, ولا Lovable Cloud مفعّل، ولا أي جدول.
- التخزين كامله **من جانب المتصفح**:
  - `localStorage` بالمفتاح `himam.pkg1a.store.v1` — يحوي كائنات الحالات والأدلة والقرارات والتقارير (JSON).
  - `IndexedDB` بقاعدة `himam-pkg1a` — يحوي ملفات الخطة الخام والنص المستخرج (Blobs).
- توليد الرمز `RC-YYYY-NNNN` تسلسلي **داخل نفس المخزن المحلي** (عدّاد مشتق من الحالات الموجودة في `localStorage` فقط).

### التفسير

| العامل                              | الأثر                                                                                                                  |
| ----------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| Preview URL vs Published URL        | لكل أصل (origin) مخزن `localStorage`/`IndexedDB` منفصل. الحالات المنشأة على رابط المعاينة لا تظهر على أي رابط آخر.     |
| «Last saved version» / إعادة البناء | إعادة نشر المعاينة تُعيد تحميل الأصول ولا تمس المخزن؛ لذا **ليست** سببًا بحد ذاتها لفقدان الحالات.                     |
| الفرع                               | الفرع يغيّر الكود لا البيانات. لا علاقة سببية بين الفرع وعدد الحالات.                                                  |
| جلسة/ملف تعريف المتصفح              | فتح المعاينة في نافذة خاصة، أو متصفح آخر، أو جهاز آخر، أو مسح بيانات الموقع = مخزن فارغ أو مختلف.                      |
| اختلاف الأصل داخل Lovable           | `id-preview--…lovable.app` و `project--…-dev.lovable.app` و `project--….lovable.app` أصول مختلفة ⇒ ثلاثة مخازن مختلفة. |

### الاستنتاج (سبب جذري)

الاختلاف **ليس فقدان بيانات في التطبيق**، بل نتيجة مباشرة لبنية Local-first مرتبطة بالأصل والجلسة: ما رآه الفاحص هو محتوى مخزن أصل/جلسة واحدة، بينما `RC-2026-0001…0004` و«ع» أُنشئت في أصل أو جلسة أو جهاز مختلف. لا يوجد داخل الكود أي مسار يحذف الحالات تلقائيًا (تم البحث: لا استدعاء `localStorage.clear()` ولا حذف جماعي مجدول).
